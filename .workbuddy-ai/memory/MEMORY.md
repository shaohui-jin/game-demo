# 爪爪乐园 · 项目长期约定

## 项目定位
对标《肥鹅健身房》「合成 + 模拟经营」双循环玩法，猫狗主题的**单机内购破解版**游戏。
目标：自己玩 + 分享给朋友打发时间。**非商业项目。**

## 硬约束（不可违反）
1. **零服务器** —— 任何功能设计前必须先确认不需要后端。已用方案：自包含分享码（非短码）、L1 手动导出导入、SaveEnvelope 数据契约预留 L3/L4 接口位。
2. **破解功能做旁路，不做改造** —— 模拟充值必须是独立模块（只负责往钻石余额加钱），所有商品逻辑完全按原版实现、一行不改。任何"破解特供"功能都不得侵入原版逻辑。
3. **美术必须完全原创** —— 玩法机制不受版权保护，但具体表达（美术、文案、音乐、UI 布局）受保护。绝不使用《肥鹅健身房》任何原版素材。
4. **金币不可充值，钻石可模拟充值** —— 不提供任何"钻石兑换金币"通道，否则经营数值挑战归零。

## 技术路线（已确认，2026-09-28 最终版）
- **技术栈：纯 HTML5（DOM + CSS + Canvas）** —— 不使用游戏引擎
- 形态：**竖屏（Portrait）· 手机为主**
- 首发形态：**网页版**（分享给朋友 + 覆盖 iOS）+ **安卓 APK**（Capacitor 打包，自己玩，存档落本地文件）
- 桌面版 exe：可选，Tauri 打包
- iOS 限制：无法自行打包，只能走网页版；Safari 会清理 IndexedDB，需强化备份提示

**为什么放弃 Cocos Creator（用户最终决定）**
1. Cocos 需在 GUI 编辑器手工搭场景，无法代码化交付，个人项目效率损耗大
2. 合成经营游戏约 80% 内容是 UI（棋盘/商店/图鉴/订单/装饰），DOM + CSS 效率远高于游戏引擎
3. Cocos 核心能力在 Web 上均有替代：粒子→Canvas 2D 叠加层；骨骼动画→Rive；序列帧→Lottie；WebGL 批量→PixiJS（本项目用不上）；多端打包→Capacitor/Tauri
4. 纯 Web 无构建流程，改一行刷新即见，调手感调数值效率高一个数量级

**技术要点（原型已验证）**
- 拖拽用 Pointer Events，不用 HTML5 Drag & Drop（移动端支持差）
- 棋盘 `touch-action: none` 防拖拽时滚动
- 拖拽元素 `pointer-events: none` + `document.elementFromPoint` 判落点
- 棋盘宽度 `min(100%, calc((100vh - 340px) * 7 / 9))` 按视口反推，保证 7×9 落首屏
- 粒子层：全屏 fixed canvas，按 devicePixelRatio 缩放，`pointer-events: none`
- **产出必须随机位置抛出**（不得按顺序填空格）：`pickRandomEmpty()` 随机选空格 + `flyTo()` 抛物线飞行（水平线性 / 垂直正弦弧 / 随机时长 300–410ms / 随机弧高 46–98px / 随机旋转方向与角度）。时长、弧高、旋转**三者均需随机**，否则连续产出会有机械节奏感。目标格物品先加 `.pending` 隐藏，飞行落地后移除并加 `.landed` 弹跳
- **★ 铁律：先取位置，再改数据**。`renderBoard()` 会用 `dataset.k !== itKey(it)` 重建变化的物品元素；一旦元素被重建，`getBoundingClientRect()` 会返回全 0，导致粒子/飘字跑到屏幕左上角。所有源位置 rect 与中心点**必须在改动 state 之前**取好；`flyTo()` 接收 rect 而不是元素

## ★ 核心玩法：发射器体系（原版术语是"发射器"，不是"生成器"）
**不是**一组平行的线性合成链，而是**发射器驱动的树**。完整拆解见 `肥鹅健身房-玩法机制拆解.html`。

### 发射器分两类（行为完全不同，这是最关键的一条）
| 类型 | 行为 | 来源 |
|---|---|---|
| **主要发射器** | 只有 CD，**不会消失、不会降级** | 开局自带 |
| **次级发射器（母体）** | 会消失/降级/需吞道具；产出总量**固定**，点完**连带发射器一起消失**，等于"一个物资包" | **全部由主要发射器发育合成而来** |

→ **母体是一次性物资包，不是永久工具。核心循环是"不断重新发育母体"。**

### 发射器三属性
1. **产出表**：一个发射器产出 **1~3 种**物品，且有**掉落概率**
2. **点击次数**（耐久）：点满即消耗掉自己
3. **冷却**：主要发射器看 CD，次级发射器看剩余次数

### 链的终点只有两种
1. **母体**：点击产出**另一条链**的低级物品。**不可再合成**、有耐久、用完消失
2. **纯任务物品**：只交订单，**不可合成、不可点击**

### ★「母体不可合并」的准确含义（用户明确指正）
发射器**可以出现在链的中段**（手提包 Lv1/Lv2 都可点击、可合并升级，次数 10→22），但**链的顶点是终点、一旦到达就不能再合并**。母体就是那个顶点。

### 关键实例（攻略原文，验证机制用）
```
2 个工具箱把手 → 1 个箱盖 → 2 箱盖 → 1 个空箱子 → 2 空箱子 → 1 个简单五金盒
"简单五金盒可以开始生产工具啦，但是只能生产起钉器和单只手套噢"
```
→ 一个发射器**产出多条链**（手套链 + 工具链），不是一对一。
→ **发射器可以产出别的发射器**：购物车 → 工具箱（工具箱本身也是发射器）。

### 点击次数实测（社区整理）
黑色手提包 Lv1/Lv2 = 10/22 ｜ 粉色手提包 = 12/28 ｜ 小·中·大肥鹅 = 15/18/53
- "点剩最后一次再合成"：点满次数发射器就被消耗，必须两边都留"没点完"状态才能合成
- "2 级点了会影响三级次数" → **点过的次数会带到合成结果里**

### ★ 设计洞察（所有数值设计都要服务于这一条）
**游戏真正的乐趣不是"合成"（机械动作），而是"资源分配决策"**：什么时候点、点到几级、留着还是合掉、优先发育哪条链。
社区技巧印证：运动器材 5 级就够（存在最优停止点）／ 前期别搞冠军杯（陷阱链）／ 1 级不要点合成 2 级再点（非线性成长）／ 次级发射器别急着点（不可逆定量资源）

### 原型落地形态
玩具链(3级)→🏰猫城堡【母体·耐久8·用完消失】→护理链(3级)→💈美容台【母体】→食物链(3级)→🍱豪华鲜食【纯任务】
- 棋盘物品结构：`{c:'toy', l:4, u:8}`（`c`链 / `l`等级 / `u`剩余耐久，仅母体有）
- 订单结构：`{c, l}`，只从已解锁链抽取

## 核心设计参数
- 棋盘 7×9=63 格，初始解锁 35 格（前 5 行）
- 合成规则：二合为一。**链最高等级恒为「普通物品数 + 1」**（顶端唯一，且不可合成）
- 合成链：猫派 5 条 + 狗派 5 条 + 共用 4 条（正式版），原型先用 3 条串成树验证机制
- 订单：基础 15 经验 / 30 金币 / 40 好感，每 5 级 +20%
- 商城刷新：6:00 / 12:00 / 18:00 / 24:00
- **震动：全项目只有一个振幅常量 `SHAKE_AMP = 1.0`，所有合成与升级完全一致，不做分级、不做递增。** 设 0 即全局关闭
  - **原则：屏幕震动不能按像素大小判断是否克制，只能按发生频率判断。** 震的是整个 `#app`，眼睛会跟整帧走，整屏位移的感知强度远高于同振幅的局部动画
  - 等级反馈由**局部粒子递增**承担（`lvBoost = min(lv,6)*2` 加到粒子数与扩散环半径上）

## 体力系统（已确认，2026-09-28）
- 自然恢复：**每 2 分钟 1 点**，到上限停止累积（不攒溢出量）
- 上限：**100**（自然恢复上限）
- 每日补贴：**12:00 / 18:00 / 24:00** 三段，每段领一次，**只认当前时段、过期作废、不补发**
- 补贴数量：50 点/次，**可突破上限**
- 点击消耗：**恒定 1 点**
- 日均可用约 870 点（自然 720 + 补贴 150）；从 0 回满约 3.3 小时
- **设计理由：定点回满会逼玩家卡时间点上线，是负担；连续恢复+三段补贴 = 不上线不亏、上线有小惊喜**

## 格子解锁（已决策）
- **不照搬原版**。用户反馈原版后期可能不再用金币开格（新手期才用），按《爪爪乐园》自有钱币体系重新设计

## 次数继承规则（已定稿：甲 · 重置为满）
已点过若干次的发射器被合并成高一级时，新的耐久**一律回满、不继承剩余次数**。用户裁定原话："甲吧，算是给用户的一个隐藏福利机制了"。

**★ 重要认知修正**：我原先判断"甲让最优解固定为合前点到剩 1 次、无真实决策"——**这个判断只在单级链里成立**。
甲真正的价值前提是**存在跨等级发射器链**（原版手提包 Lv1/Lv2 都可点击）：
点剩最后 1 次 → 合成后回满 → **中间点掉的次数全部白赚**。于是"什么时候停手"变成有正收益的取舍
（点掉=立刻换低价值产出，留着=延迟换高价值产出）。**结论：甲在单级链里是坏规则，在跨级链里是好规则。**
配套要求：合成后必须弹提示把"白赚 N 次"显性化，否则隐藏福利等于不存在。

**资料侧三条证据互相矛盾**（"点剩最后一次再合成" / "2 级点了会影响三级次数" / "Lv3=53 远高于 Lv1=15"）→ 连玩家社区都没搞清楚，属可自由定义的设计空间。

## ★ 代码层约定（P0 原型，踩过坑）
- **区分「原始链定义」与「defOf() 返回值」**：`CHAINS[k].items[i]` 的字段是 `click:{charges,drops}`，而 `defOf(k,lv)` 返回的对象把 `charges` / `drops` 提到顶层并给出 `kind` / `produces`。**两者字段不同，绝不能混用**（曾在 `renderTree` 里对原始定义取 `.produces` → 启动即崩）。
- **`defOf()` / `maxLv()` 对未知链必须返回 `null` / `0`，不能抛错**：旧存档的孤儿物品会走到这里，一抛错就被 `load()` 的 catch 吞掉 → **整份存档被静默清空**。宽泛的 try/catch 是存档杀手。
- **任何改动 state 的分支都必须自己负责重建 DOM**，不能依赖别的分支顺手调用 `renderBoard()`（资源掉落分支曾因此不刷新耐久徽标）。
- **改动 state 前先取好 `getBoundingClientRect()`**：`renderBoard()` 会重建元素，重建后 rect 全为 0。
- 可点击的发射器分两类，视觉上用边框区分：**顶端母体**（`.gen` 实线边框）与**链中段发射器**（`.mid` 虚线边框）；两者都带 `.gen` + `.ready/.dry` 做脉冲/置灰。
