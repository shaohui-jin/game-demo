手绘贴纸风

核心一句话：整个世界是一本贴纸册。每个物品、按钮、面板都做成一枚「模切贴纸」——外面一圈实心白边，底下 3px 硬落影，错位只留给胶带和便利贴。比治愈系更跳、更像玩具，也正好接住你拆解文档里那句「标题做胶带／贴纸样式 + 卡通描边卡片，整体像玩具而不像系统弹窗」。颜色仍沿用工程里的 token，可逐屏替换。

贴纸语言规范

白边 · 投影 · 错位 · 九宫格

01色彩系统

贴纸风要做两件事：底色退到纸上（暖米黄大面积铺底），物件提饱和（物体本身是彩色贴纸）。所以链色比治愈系版整体提了一档彩度，但仍在同一色相内递深——保证七格同屏不跳色。

02贴纸的四条构成规则

这四条必须一致，否则贴纸感立刻散掉。第 4 条最容易做错，单独展开在下面。

要素规格为什么
模切白边白色实心外扩 3px，沿造型轮廓（不是矩形）这是「贴纸」和「图标」的唯一分界线。没有白边，造型再可爱也只是扁平图。
硬落影先一层 0 3px 0 实心影，再叠一层柔影只有柔影会变成「浮起的卡片」；加一层 0 模糊的实心影，才是「撕下来的贴纸」。
手作错位只用在一眼能看出是"纸"的元素上：胶带标题、便利贴说明。功能性元素（币条 / 按钮 / 卡片 / 列表行 / 棋盘物品）一律对齐。见下方警告 —— 这是最容易做过头的一条。
压进纸面按下时：硬影消失 + 下移 3px模拟手指把贴纸按平的物理感，比缩放/变色更符合这套语言。
第 1 条为什么最容易做错：白边必须沿造型轮廓。用 CSS 的 box-shadow: 0 0 0 3px #fff 只能得到矩形白边——遇到带细杆或镂空的造型（剪刀、逗猫棒、蛛网）立刻露馅。正确做法是把白边烘进贴图本身，见下方产出流水线。
第 4 条为什么最容易做过头（已实测踩坑，务必先读）： 一开始我把 ±1~3° 的随机旋转铺到了**所有**元素上——币条、按钮、卡片、列表行、棋盘物品。结果不是"手作感"，而是像渲染坏了： 文字歪着读起来像出错，棋盘上的物品更是明显降低扫读速度。
现在的口径：旋转只保留在"物理上就是一张纸"的元素上（胶带标题、便利贴说明），其余一律对齐。 贴纸的身份靠模切白边 + 硬落影撑就够了 —— 这两条才是不可让的，旋转是可选项，且默认关。

03面板与按钮 · 九宫格（9-slice）

面板、按钮、气泡全部走九宫格。白边可以跟着九宫格走，投影不行——投影必须由 CSS 补（box-shadow），否则面板拉长后底部的影会被一起拉扁。

四角不拉伸，保留完整圆角 + 白边转角。切图四角各取 56×56（对应设计稿 18px 圆角 / 3px 白边 / 2px 描边）。
四边单向拉伸。必须是可平铺的纯色或竖向渐变；纸面允许有一点点噪点，但噪点要做成 tileable，否则拉长会出条纹。
中心双向拉伸或留空。不要放纸纹或斜向纹理——二维拉伸会把纹理拉成面条。
投影不进九宫格，交给 CSS：box-shadow: 0 3px 0 rgba(...), 0 12px 24px rgba(...)。

04按钮状态

只做三态，且三态的区别是物理关系而不是颜色：常态浮起、按下压平、禁用降透明（但保留白边，别让贴纸直接消失）。不做 hover——移动端没有 hover，做了是白做。

05物品贴纸清单

这是需要资产化的全部造型，每个造型有唯一资源键。每个键对应两张资产：一张带白边的成品贴图（代码直接用）、一张不带白边的造型源（改色与二次导出用）。代码只认键，换美术不动逻辑。

06字号层级

贴纸风的字要更重：细字压不住厚白边和硬投影，会被视觉吞掉。所以整体比治愈系版提了一档字重，正文也不再低于 600。全项目只有这五档。

07现状与改版对照

左边是现在的实现（emoji 字形贴在素色格子上），右边是贴纸版。差别不只是好不好看——左边无法控制：字形由系统决定，iOS / Android / Windows 各长一个样。

PIPE

贴图怎么产出、怎么被代码吃掉

五步流水线 · 可直接执行

A产出流水线

造型用矢量出稿（改得最快），成品必须是位图（因为白边和投影要烘进去）。第 2 步是这套风格新增的关键工序，下方单独展开。

STEP 1
造型定稿
按本稿清单出矢量造型，不带白边。这一层是外包美术唯一需要交付的东西。
STEP 2
复制一份加白边
在矢量层给造型加「外描边」：白色、沿轮廓外扩 3px、圆角连接。得到带白边的成品造型。
STEP 3
导出位图
统一 @3x 导出 PNG 透明底。逻辑 48px 的格内物品 → 导 144×144，边缘才不发虚。
STEP 4
压成 WebP
PNG 压 WebP（带 alpha）。贴纸风色块大、颜色少，WebP 通常能压到 PNG 的 25%~35%。
STEP 5
代码消费
物品走 background-image，面板走 border-image。投影、旋转、按下态全部交给 CSS。

B模切白边怎么产出（三选一）

这是贴纸风唯一新增的工序。三种做法的差别是「出图时多花时间」还是「运行时多花性能」——你这项目明确以中低端安卓为性能基准，所以推荐 A。

做法怎么落地代价适用
A · 设计工具加外描边
（推荐）		导出前加「外描边 / Outline outside」：白色、3px、沿轮廓。随贴图一起导出。出图时多一步，运行时零开销；缺点是改色要重导。全部正式资产
B · 脚本做 alpha 膨胀对 PNG 的 alpha 通道做 3px dilate 填白，与原图合并，可写成构建脚本批量跑。要写一次图像脚本；对细杆造型（剪刀）容易断线。批量替换 / 不想手工出图
C · CSS 八向 drop-shadowfilter: drop-shadow(0 0 0 #fff) 叠 8 个方向，确实能沿 alpha 轮廓生成白边。性能代价大：棋盘 35 格 + 背包 25 格同屏，等于 500+ 次阴影合成，中低端安卓必掉帧。只做原型验证，不进正式包
为什么不能只用 CSS：贴纸风的灵魂是白边跟着造型走。任何靠矩形外框做出来的白边，在剪刀、逗猫棒、蛛网这类带细杆或镂空的造型上都会穿帮——这一条没法绕。

C目录与命名

命名只有一个要求：从文件名能反推出代码里的键。贴纸风每个造型多一张源图，用 _src 后缀区分，源图不打进包。

用途路径命名规格
物品贴纸assets/sprites/items/toy-1.webp144×144 · 含白边 · 透明底 · 造型居中留 8% 安全边
母体 / 任务物assets/sprites/gen/gen-fort.webp168×168 · 同上
主发射器assets/sprites/spawn/spawn-rack.webp168×168 · 同上

D代码消费方式

改动集中在一处：chains.ts 的 emoji 字段换成 sprite 资源键，加一张映射表 + 一个错位角度函数。渲染层抽象已经存在，emoji 留作兜底。

// --- 1. chains.ts：emoji → sprite 资源键（保留 emoji 兜底，渐进替换）---
{
  name: '毛线球',
  emoji: '🧶',            // 贴图缺失时不至于开天窗
  sprite: 'toy-1',          // ← 新增：唯一资源键
  bg: '#FFDCE9', fg: '#72243E', fx: '#D4537E',
}

// --- 2. sprites.ts：资源映射 + 错位角度，集中管理 ---
const BASE = '/assets/sprites'
export const SPRITE: Record<string, string> = {
  'toy-1': `${BASE}/items/toy-1.webp`,
  'care-2': `${BASE}/items/care-2.webp`,
  // …
}
export function spriteOf(key?: string): string | null {
  return key ? SPRITE[key] ?? null : null
}

// --- 3. 错位角度：由格子下标决定，保证刷新后一致、又不显规律 ---
//     不要写死角度数组，否则棋盘上会看出整齐的斜线
export function tiltOf(i: number): string {
  const r = Math.sin((i + 1) * 12.9898) * 43758.5453
  return (((r - Math.floor(r)) - .5) * 2.6).toFixed(2) + 'deg'
}

// --- 4. BoardCell.vue：贴纸容器挂角度，其余不动 ---
// 旧： <div class="item">{{ def.emoji }}</div>
// 新：
<div class="tile" :style="{ '--rot': tiltOf(index), background: def.bg }">
  <img v-if="spriteOf(def.sprite)" :src="spriteOf(def.sprite)!" alt="" />
  <span v-else>{{ def.emoji }}</span>
</div>

// --- 5. 面板九宫格 + 投影分离 ---
.modal-card {
  border-width: 15px;                    /* 15 = 18 圆角 - 3 白边 */
  border-image: url('/assets/ui/panel-card.webp') 56 fill / 15px / 0 stretch;
  box-shadow: 0 4px 0 rgba(59,46,32,.14), 0 14px 26px rgba(59,46,32,.20);
}

E替换顺序建议

按「可见收益 ÷ 改动风险」排。贴纸风有个额外好处：白边自带隔离感，新旧资产混用一屏时不会太割裂，可以放心分批上线。

批次内容为什么排这个位置
第一批棋盘物品贴纸（9 个）+ 2 个母体棋盘是玩家 90% 的注视区域，风格切换的观感差全在这里。只需新增 sprite 字段。
第二批货币 / 状态图标 + 功能栏图标出现频率最高，改完「工具感」立刻消失。独立图元，零逻辑风险。
第三批面板九宫格 + 标题胶带 + 便利贴说明纯样式改动但覆盖全部弹窗，等画布稳定后做最安全。
第四批蛛网 / 锁定格 / 空位槽 / 发射器栏状态类元素，改动少收益也小，放最后收尾。
