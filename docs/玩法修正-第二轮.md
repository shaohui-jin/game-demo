## 01 五条修正与落实情况

### ① 主场景不该有"锁定格"

**原实现（错）**：棋盘 7×9，只解锁前 5 行（35 格），下面 4 行带 🔒。
**现实现**：**整块 63 格从开局起全部可用**，`isLocked()` 已从代码里删除。

"花金币解锁格子"只属于**背包**这一个系统（5×5=25 格，初始 10 格，首格 500 金币、每格 ×1.18）。

那"格子压力"从哪来？靠两件事，都不需要锁定格：
1. **设施在棋盘上常驻占格**（玩具架 / 玩具箱 / 合成出的母体）；
2. 蛛网会临时占格，且只落在空格上。

这和 ⑤ 是同一件事的两面：正因为设施常驻占格，主场景才敢整块开放。

### ② 玩具架 / 玩具箱 变成主场景常驻母体

**原实现（错）**：它们是棋盘下方一条独立工具栏里的两个按钮，和外挂一样。
**现实现**：
- 它们是**棋盘上的对象**，开局自动占两个格；
- 可以被**拖进背包**暂存，也可以拖回棋盘；
- 两个玩具架可以合成一个玩具箱（升级线）；
- 走储备 + 冷却模型，**永不消失**。

实现方式：新增一条独立的**设施链 `fac`**（Lv1 玩具架 → Lv2 玩具箱）。设施不是"另一种东西"，
而就是"一个可点击的链物品"—— 于是拖拽、背包、存档、渲染、特效**全部复用既有机制，零新增分支**。

### ③ 棋盘 ↔ 背包双向交互

**原实现**：长按选中 → 点底部「存入」按钮；背包是全屏遮罩弹窗。
**现实现**：
- **拖**：棋盘格 → 背包抽屉格子 = 存入（背包未满）。落点会高亮。
- **点**：点抽屉里的物品 = 取出到棋盘第一个空格（棋盘未满）。
- 长按 → 「存入」保留了，作为拖拽之外的备用入口。

**为什么背包必须从「弹窗」改成「抽屉」**：全屏遮罩会把棋盘整个盖住，拖拽的起点根本看不见 —— 物理上做不到。
现在抽屉占屏幕下半部分，棋盘被压缩但仍可见可操作。压缩靠 CSS 变量 `--bag-h` 实现（写在 App 的 `.screen` 上，`.board` 作为后代继承）。

### ④ 母体是"储备耗尽才冷却"，不是"点一次冷却一次"

**原实现（错）**：玩具架点一下进 4s 冷却，玩具箱点一下进 10s 冷却。
**现实现**：节奏阀拆成两个字段 ——

| 字段 | 含义 |
|---|---|
| `buffer` | **储备上限**：一次冷却能补满的可点击次数 |
| `refillMs` | **储备耗尽后的冷却时长**（0 = 不冷却，走耗尽行为） |
| `exhaust` | 耗尽且不冷却时的行为（转化 / 消失） |

玩家可以把 8 次储备一口气点完，**点第 1 次不会进冷却**。储备归零才盖冷却遮罩 + 倒计时，到点由每秒 tick 自动补满。

### ⑤ 链路要能看懂 + 母体耗尽分类型

**原实现**：链树面板只有一行 emoji 箭头 + 一段密集文字，看不出"这条链几级、哪几级能点、点完会怎样"。
**现实现**：`ChainTreeModal` 升级为**图鉴**：
- 每条链一条横向链路图（每个节点带贴图、等级、储备/冷却）；
- 顶部三色图例，把「冷却型 / 转化型 / 消失型」摆在做前面；
- 每个可点击节点单独一行：点击产出什么、**耗尽后会发生什么**；
- 顶部显示"你现在有几个设施、几个会自我补充的产出点"。

#### 本轮定的链路语义（可直接改 `chains.ts`）

| 对象 | 储备 | 耗尽后 | 类型 |
|---|---|---|---|
| 玩具架（fac Lv1，开局常驻） | 8 | 冷却 60s 补满 | 冷却型 |
| 玩具箱（fac Lv2，2 个玩具架合成） | 12 | 冷却 90s 补满 | 冷却型 |
| 铃铛球（toy Lv3） | 5 | 消失 | 消失型 |
| **猫城堡（toy 顶端）** | 6 | **变成「伴手礼」**，接入礼包链 | 转化型 |
| 洗澡球（care Lv3） | 5 | 消失 | 消失型 |
| **美容台（care 顶端）** | 8 | 冷却 120s 补满 | 冷却型 |
| 鲜鱼排（food Lv3） | 5 | 消失 | 消失型 |
| 豪华鲜食（food 顶端） | — | 不可点击（纯任务物品） | — |
| 伴手礼（supply Lv1） | 8 | 消失 | 消失型 |
| **豪华礼盒（supply Lv2）** | 18 | **变成一个玩具架**（白拿一个常驻设施） | 转化型 |

**为什么这样分**：冷却型负责"无尽产出"（稀缺的是体力与空间，不是基础物品）；转化型负责"链路衔接"
（猫城堡 → 伴手礼 → 豪华礼盒 → 玩具架，形成闭环）；消失型**只留给链中段**，保住「甲·重置为满」那条取舍 ——
如果所有发射器都永不消失，合成链的决策深度会塌掉。

## 03 顺带修掉的两个真实 bug

1. **`countFacilities()` 会让整份存档加载失败。**
   它被 `ensureFacilities()` 从**存档归一化流程**里调用，而那是老存档进来时的第一站 ——
   此时 `s.bag` 可能根本不存在（旧版本没有背包）。直接 `for...of s.bag` 会抛
   `TypeError: s.bag is not iterable`，异常冒到 `load()` 外面 → **整份存档加载失败**。
   这类"宽泛的 catch 是存档杀手"正是本项目最贵的一类故障。已改为对残缺 state 免疫 + 补回归测试。

2. **`ensureFacilities()` 的位置错了。** 原来放在背包归一化**之前**，
   于是"设施全收进背包"的玩家每次读档都会被重复补发两个设施。已移到背包块之后。

另外修了一个设计漏洞：**背包会变成跳过冷却的漏洞**。如果只把物品搬进背包而不挂起冷却，
"冷却中的设施塞进背包再拿出来"就白拿一次补满。现在用 `cdLeft` 字段把剩余冷却挂起，
取出时换算回新的时间戳（`suspendCooldown` / `resumeCooldown`），并有单测锁住。

## 04 测试

`npx vitest run` → **148 例全绿**（纯逻辑 89 + 整机 59）。本轮新增 20 例，重点覆盖：

- **储备模型**：连点只扣储备、不进冷却；耗尽才进冷却；冷却中点击不扣体力；到点由 tick 自动补满
- **三种耗尽行为**：猫城堡 → 伴手礼、豪华礼盒 → 玩具架、链中段 Lv3 消失
- **背包冻结含冷却**：挂起 60s → 在背包里放 10 分钟 → 取出仍剩 60s
- **设施保护**：不能被蛛网牺牲
- **拖拽落点**：`.bag-cell[data-bag]` 存在、抽屉不是遮罩弹窗、棋盘与抽屉同屏
- **图鉴**：5 条链都渲染、节点数正确、三种耗尽行为各有标注
- **存档**：`cdAt` 状态跨存档存活（刷新页面不能白拿补满）；残缺 state 不抛错；设施全在背包时不重复补发

构建：`npm run build` 通过（192.7 KB JS / 37.4 KB CSS，gzip 64.3 / 7.8 KB）。

## 05 我替你定的默认值（要改直接说）

这几条你没明确指定，我按"链路最好懂"的原则定了默认值：

1. **储备 / 冷却的具体数值**：玩具架 8 次 / 60s、玩具箱 12 次 / 90s、美容台 8 次 / 120s。
   直接改 `chains.ts` 的 `buffer` / `refillMs` 即可。
2. **三条链的耗尽行为分配**：见上表。特别是「猫城堡 → 伴手礼」和「豪华礼盒 → 玩具架」这两个转化，
   是我为了做出"链路衔接"和"白拿设施"两个爽点定的，你可能想换。
3. **设施不可被蛛网牺牲**：这是我加的保护。不加的话玩家吃掉最后一个设施就彻底失去产出能力（死局）。
4. **拖拽进背包需要先打开抽屉**：没做"拖到底部自动弹出背包"。如果需要，可以加。
