## 02 背包的六条设计规则

### 2.1 分类页签 + 自动入库

两个页签 `元素` / `发射器`，各自独立容量。图 2 的底部文案直接给出规则：**「发射器元素会优先存入发射器页签内」** —— 即入库是**自动按类别分流**的，不需要玩家手动整理。

**为什么这条对《爪爪乐园》特别值钱：** 我们的「母体 / 链中段发射器」有一个结构性矛盾 —— 它们**有耐久、用完即消失**，玩家既舍不得点又想留着发育，结果长期占着格子。给发射器单独一个页签，等于把「留着还是点掉」这个决策**从"占不占格子"里解耦出来**，决策质量会明显提升。

### 2.2 页签直接写「已用 / 上限」

`元素 30/33`、`发射器 15/15`。把"快满了"的压力写在玩家第一眼看得到的地方，而不是藏在某处数字里。`15/15` 本身就是一种"该清理了"的提示。

### 2.3 每格左上角一个详情入口

每个物品格左上角有一个蓝色小按钮，点开是物品详情/来源说明。**弹窗里没有棋盘底部那条提示栏可用**，所以详情入口必须内嵌到格子本身。我们棋盘上现在是「轻点物品 → 底部提示栏显示详情」，这个方案在弹窗场景里会失效。

### 2.4 页签内部也能逐格解锁

图 2 第一行 5 格是金色锁格，扩容格上也挂着锁。**背包本身是一个可成长系统**，而不是一次性送满的功能。图 1 的扩容格标价 `224000` 金币 —— 价格是显性的、高的，构成一个长期金币回收池。

### 2.5 堆叠

图 1 中有一个物品右下角标 `x1`，说明**部分物品可堆叠**，一格放多个。这直接压缩了格子占用 —— 对"格子压力"是釜底抽薪，而不只是缓冲。

### 2.6 底部一行小字解释规则差异

两个页签的底部文案**不同**：元素页说「无法恢复时间」，发射器页说「会优先存入发射器页签内」。用一行 11px 小字就地解释**这个页面特有的反直觉规则**。

> **这条我们最该抄。**《爪爪乐园》有两条反直觉规则：① 母体是「一次性物资包」、用完即消失；② 「甲·重置为满」——合成后耐久回满、点掉的次数白赚。方案文档里已经写明"福利必须让玩家看见，藏着不说等于没有"。而这种**贴在使用现场的一行小字**，比弹一个 Toast 更持久、更省打断。

## 03 界面设计的其他可借鉴点

| 位置 | 参考做法 | 我们的现状 |
|---|---|---|
| 空位占位 | 空位画成**深色五角星**，与"已锁定"明显区分 | 我们用白底空格 + 锁定行灰底 🔒，区分度够；但"空格"和"可用但空着"没有视觉强化 |
| 不可用角标 | 物品上叠一个**红色禁止符号** | 我们没有"该物品当下不可操作"的提示（例如母体耐久耗尽前只剩 1 次、或棋盘将满时） |
| 发射器栏 | 每个设施带**三个数字**：储备量 / 容量上限 / 耐久（`0/1`、`0/2`） | 我们的主要发射器只有「CD + 冷却条」，没有"储备量"概念 —— 是否要加需要裁定 |
| 顶部 HUD | 一行塞下：等级 + 倒计时 / 金币 / 钻石 / 活动入口 / 好感 / 进度 / 离线时长 | 我们只有体力 / 金币 / 钻石三个币。等级、经验、好感度都还没有入口 |
| 弹窗视觉 | 标题做「胶带 / 贴纸」样式 + 卡通描边卡片 + 米色内容面板，整体像玩具而不像系统弹窗 | 我们目前是纯白圆角卡片，偏"工具感"。猫狗主题可以更玩具化 |

## 04 落地优先级建议

1. **先做"就地解释"这一条**（第 2.6 节）—— 零成本、立刻见效，且直接服务于已定稿的「甲·重置为满」。
2. **再做"发射器单独收纳"**（第 2.1 节）—— 它解决的是我们结构上真实存在的矛盾，只是需要一个承载形态（背包 / 收纳架 / 页签皆可）。
3. **堆叠与扩容**留到数值体系稳定后再定 —— 它们会连带改动合成交互与金币回收池，不宜先做。
4. **视觉玩具化**（标题贴纸、卡通描边）可以随时做，不影响任何逻辑。

## 05 裁定结果与已落地实现

四条问题已全部裁定，并已在 Vue 工程里落地。

| 问题 | 裁定 | 落地要点 |
|---|---|---|
| 背包形态 | 纯收纳箱，可以金币拓展格子；**外部场景是固定个数的** | 棋盘格数固定不变，**格子类金币回收池全部落在背包上**。背包容量 5×5=25，初始解锁 10 格，首格 500 金币、每格 ×1.18。背包内物品冻结：不能点击产出、不走 CD、不消耗耐久。`价格梯度待调` |
| 入库方式 | 手动拖入；**棋盘满的话不允许再往外发射元素** | 不做自动分流入库。棋盘满时产出直接拒绝（沿用原逻辑，提示"先合成、清除蛛网或交付订单"）。入包入口改成长按选中 → 底部出现「存入」。 |
| 背包内发射器 | 不能点击但保留状态 | 耐久原样保留，取出后继续可用；背包里点它不会有任何产出。 |
| 堆叠 | x1 的是**特殊道具**（剪刀 / 升级卡），其他物品一律不合并，需要做特殊标识判断 | 新增 `ToolKey` + `BagSlot` 判别联合：道具可堆叠带数量、右下角显示 xN、虚线描边 + 橙色角标做特殊标识；普通物品仍然一格一个。 |

### 5.1 新增的特殊道具

| 道具 | 效果（按裁定实现） | 校验 |
|---|---|---|
| 剪刀 ✂️ | 把一个 Lv2 及以上的物品**拆成两个低一级的** | Lv1 拆不了；棋盘没有余位放下两个时**不生效也不消耗** |
| 升级卡 🎟️ | 把一个物品**直接升一级** | 已是链的顶端时无效，且**不消耗道具** |

> **与主方案存在一处冲突，需确认：**
> `爪爪乐园-游戏设计方案.html` 第 4.4 节把剪刀定义为「将发射器剪成低一级，**同时释放其已储存的产物**」；本轮裁定的是「将高等级**拆成两个低一级的**」。
> 两者不是同一件事：前者是**降级 + 结算**，后者是**一分为二**。现已按本轮裁定实现（一分为二），但主方案文档尚未同步 —— 需要决定是改文档还是改实现。

## 06 待裁定（当前未决）

### A · 剪刀的口径统一

- **背景：** 主方案 4.4 节写的是「剪成低一级 + 释放已储存产物」，本轮实现的是「一分为二」。两者语义不同，必须二选一。
- **选项 1：** 改主方案文档，统一为「一分为二」（不动代码）。
- **选项 2：** 改实现，回到「降级 + 结算已储存产物」（需要重写 `applyToolAt` 里的剪刀分支）。

### B · 「外部场景是固定个数的」具体指什么

- 暂按「棋盘格数固定、不做金币扩容」实现（棋盘维持 35 个已解锁格）。
- 若原意是"区域/场景数量固定"，规则要另算 —— 需要确认。

### C · 特殊道具的正式获取途径

- 目前只在新开局送了 1 把剪刀 + 2 张升级卡用于验证。
- 正式途径：商城金币购买？钻石购买？活动掉落？关卡奖励？

### D · 背包扩容价梯度

- 500 金币起、每格 ×1.18，是按现阶段订单收益（Lv1 30 / Lv2 57 / Lv3 108 金币）反推的。
- **需要按想要的手感校准**：希望玩家大约玩多久能开满 25 格？

### E · 道具能否批量使用

- 目前一次用一张、用完自动退出待用态。
- 要不要支持"连续使用"（保持待用态直到主动取消）？

### F · 背包内能否直接交付订单

- 若不能，卡格子时玩家仍需把东西搬回棋盘，缓解程度会打折。
- 需要定：订单需求物品可直接从背包扣除 / 必须搬回棋盘。

### G · 图 3 的红色禁止角标

- 含义推断：不可移动 / 不可合成 / 还是工具占用中？需要以实际游玩经验确认。
- 若成立，可用于标记"该物品当下不可操作"（如母体剩余次数不足、棋盘将满）。

### H · 发射器栏的「储备量」概念

- 图 3 设施上的三个数字，我读作「储备量 / 容量上限 / 耐久」，需确认。
- 若成立：我们的主要发射器是否也要引入"攒着不取"的储备量？

### I · 页签配色与背包等级

- 两图里「元素」始终米黄、「发射器」始终橙，**颜色不随选中态变化** —— 每个页签固定配色，还是误判？
- 图 3 写了"背包 1 级"，说明背包有等级：扩容消耗的是金币，还是随背包等级自动解锁？
