## 02 批次定义

### 批次 A · 已完成（前两轮）

- 玩法底座：棋盘、合成、设施链、母体三种耗尽行为、体力、蛛网、背包、特效层
- 经营层骨架：订单 4 档位 + 顾客、9 个区域、11 件装饰、8 位顾客 + 常驻宠物
- 工程：存档（含旧档迁移）、148 例测试、Vue3 + TS + Pinia 工程化

### 批次 B · 内容扩容 ← **已完成（2026-10-02，仅剩自动型）**

| 项 | 内容 | 体量 | 状态 |
|---|---|---|---|
| 合成链加深 | 3 个普通等级 → **7 级 + 顶端 = Lv8**（礼包链 4 级、设施链 3 级） | L | ✅ |
| 产出速率重算 | 设施掉落表随等级上移（Lv8 约 3 分钟纯点击，体力仍是限速项） | M | ✅ |
| 道具补齐 | 充能器 / 加速沙漏 / 能量球（2/4 → **5 种**） | M | ✅ |
| 手动型发射器 | 落地为**每日免费领 1 个玩具架** | S | ✅ |
| 自动型发射器 | 按等级定时自动释放（需要"离线按秒结算 + 累积上限"机制） | M | ❌ **未做** |

详见 `docs/内容扩容-第三批.md`。

**为什么它要排第一（已兑现）**：它一次修掉两个**结构性**问题 ——

1. **订单档位失去区分度**：`稀有` 与 `紧急` 曾都退化成"要 Lv3"。链加深后区间**两两不重叠**（普通 1–3 / 进阶 4–5 / 稀有 6–7）。这是**经济与订单**模块真正的完成条件，不是补几个按钮。
2. **"优先发育哪条链"这个取舍不存在**：3 级链走两步到顶。现在是 7 级 + 顶端，且每条链在 Lv3 与 Lv6 各留一个中段发射器 —— 「甲·重置为满」的隐藏福利从"一次"变成"两次可选"。

**下游解锁**：批次 C（商城需要"值得买的东西"：材料箱、发射器购买与升级都依赖更深的链）。

|---|---|---|
| 商城 | 6/12/18/24 点刷新、材料箱（500/2000/8000 金币）、加速沙漏、剪刀、发射器购买与升级 | L |
| 模拟充值 | 充值档位、模拟支付流程、钻石到账 | M |
| 钻石出口 | 体力补充、稀有道具、抽奖机、会员卡、成长基金 | M |
| 抽奖机 / 会员卡 / 基金 | 原版消费结构的三个长线池 | M |

**红线**：**金币只能由玩法产出**，不提供任何"钻石兑换金币"通道 —— 否则经营数值挑战归零（设计文档 15 章列为中风险）。这条在实现时要写成硬约束 + 单测。

### 批次 D · 收集与长线

| 项 | 内容 | 体量 |
|---|---|---|
| 收集图鉴 | 元素 / 装饰 / 顾客三类收集度（现在只有"链路图鉴"，那是规则说明不是收集） | M |
| 24 只角色 | 品种 + 性格 + 口头禅 + 喜好 + 3–5 幕好感剧情（现在 8 只，只有标签与口头禅） | L |
| 装饰摆放 | 位置 / 朝向 / 外观 / **多套方案槽位**（现在是"装饰墙"：只能购买升级） | L |

| 宠物代打 | 常驻宠物派遣去点发射器 N 次（放置收益从"资源"延伸到"操作"） | M |

**前置依赖**：批次 C（抽奖机是卡牌/造型的来源；且好感剧情需要钻石出口支撑获取节奏）。

### 批次 E · 存档安全与分发（**可与 C / D 并行**）

| 项 | 内容 | 体量 |
|---|---|---|
| 多槽位自动备份 | 轮转备份，防止单文件损坏 | M |
| 导出 / 导入 JSON | L1 本地方案；首次启动提示备份 | M |
| SyncAdapter 接口 + SaveEnvelope | 数据契约（schemaVersion / deviceId / checksum）。**现在落实，未来接服务端零改动** | M |
| 打包分发 | 优先安卓 APK，其次网页版 | M |

**为什么它不该拖到最后**：设计文档 16 章明确「存档安全应排在玩法之前」——
单机版的进度就是玩家全部资产，且要**分享给朋友**，朋友丢档 = 体验直接崩。
现状已有完整迁移与容错，但**还没有备份与导出**，这是当前最大的单点风险。

| 项 | 内容 | 体量 |
|---|---|---|

**说明**：音效与动画打磨虽然排在这里，但**合成手感的调优不应该等到最后** ——
设计文档 16 章第一条就是「先做 P0 验证手感，纸面方案无法评估」。建议在批次 B 结束后立刻做一轮真机手感评估。

## 03 关键依赖链

```
批次 B 内容扩容
   ├─→ 批次 C 经济闭环（商城要有货可卖）
   │        └─→ 批次 D 收集与长线（抽奖机 → 卡牌/造型；充值 → 剧情获取节奏）
   └─→ 订单档位重新有区分度（经济与订单模块才真正完成）

批次 E 存档与分发  ← 不依赖任何批次，可全程并行
```

**唯一的强依赖是 B → C**：先做商城会是个空架子（材料箱、发射器升级都还没有）。

## 04 与设计文档第 14 章的对照

| 文档阶段 | 文档原计划 | 实际 | 说明 |
|---|---|---|---|
| P0 原型（1–3 周） | 骨架 + 棋盘 + 2 发射器 + 1 条链 | **超额完成** | 升级成 Vue 工程；发射器模型重做；新增设施链 |
| P1 核心（4–7 周） | 体力 + 星星装饰 + 区域 + 6 条链 + 商城 + 模拟充值 + 存档 + SyncAdapter | **约 55%** | 体力✅ 区域✅（做了 9 个，超额）存档✅ ｜ 缺：链到 6 条、商城、模拟充值、SyncAdapter |
| P2 完整（8–10 周） | 10 条链 + 9 区域 + 图鉴 + 24 角色 + 常驻宠物 + 会员卡/基金/抽奖机 | **约 40%** | 9 区域✅ 常驻宠物✅ 链路图鉴✅ ｜ 缺：10 条链、收集图鉴、24 角色、三个长线池 |
| P3 内容与分发 | 节日活动 + 角色扩展 + 打包分发 | **0%** | — |

**两处错位要注意**：

1. **P1 被"跳着做"了** —— 区域与经营层提前完成，而合成链加深、商城、模拟充值落后。原因是我在第一批里选了"影响力最大的一组"（经营层闭环，因为长期目标链当时是断的）。
2. **文档的"6 条链"是不够的** —— 文档默认链有 8 级，而加深到 8 级意味着 Lv8 需要 128 个 Lv1。以现在的产出速率（玩具架 8 储备 / 60s 冷却）算，一条 8 级链的加速比会非常陡。**批次 B 不能只加等级，必须同时重算产出速率与体力消耗**，否则会把游戏变成"等得难受"。这一项应算进批次 B 的体量里。

## 05 风险对齐

| 风险（文档 15 章） | 等级 | 由哪个批次覆盖 |
|---|---|---|
| 美术原创性 | 高 | 全程（现有贴图层已是原创 SVG；换正式素材时守住不用原版） |
| **存档丢失** | 高 | **批次 E** ← 当前最大的单点缺口 |
| 金币数值挑战被破坏 | 中 | 批次 C（金币不可充值 + 单测锁定） |
| 内容量不足 | 中 | 批次 D + F（目标 40+ 小时） |
| 浏览器存档脆弱（IndexedDB） | 中 | 批次 E + 引导桌面端 |

---

## 06 建议

如果只做一件事：**批次 B**。它修的是"游戏好不好玩"的地基。

如果做两件事：**B + E**。E 的体量不大（M×3），但它是"分享给朋友"这件事的前提 —— 朋友丢档一次，这个项目在他那里的口碑就结束了。

C 可以等 B 完成后再启动；D 和 F 是可以慢慢加的内容层。

### ⚠️ 设计文档第 14 章的 10 周排期已经失效

文档写的是"P0 三周 + P1 四周 + P2 三周 = MVP 十周"。**这条基线现在不成立**，两个原因：

1. **范围比文档大。** 文档没列、但已经做掉的：背包系统（原版没有，是我们的自研设计）、经营层三件套（区域 / 装饰 / 顾客）、链路图鉴、母体的三种耗尽行为、链深从 3 级到 8 级、19 张原创贴图。
2. **文档的估时本身偏乐观。** 它把"24 只角色 + 3–5 幕剧情 + 9 个节日活动 + 上百种造型"压在 P2 的三周里，而这三项按内容量算就接近 4 周。

所以**以本节的 12.5 周为准**，把文档第 14 章当成阶段划分（P0/P1/P2/P3）而不是工期承诺。
