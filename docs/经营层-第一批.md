# 经营层 · 第一批实现说明

> 补齐设计文档 1.3 里**原本完全空缺**的三个子系统：**区域 / 装饰 / 顾客**，外加订单档位与倒计时。
> 实现时间：2026-10-02 ｜ 状态：已实现并通过测试（120 例）｜ 构建通过

---

## 01 为什么是这三个

扫了一遍 13 个子系统的实现情况，缺口的形状很清楚：

| 层 | 子系统 | 第一批之前 |
|---|---|---|
| 合成层 | 主棋盘 / 发射器 / 合成链 / 道具 / 体力 | ✅ 有 |
| 经营层 | 订单系统 | ⚠️ 有，但只给金币+经验 |
| 经营层 | **星星与装饰** | ❌ 没有 |
| 经营层 | **区域解锁** | ❌ 没有 |
| 经营层 | **图鉴** | ❌ 没有 |
| 外围层 | **商城** | ❌ 只有一个假按钮 |
| 外围层 | 卡牌 / 造型 / 活动 | ❌ 没有 |

**核心问题不是"少几个功能"，而是长期目标链是断的**：玩家升级除了解锁下一条链之外没有任何东西可期待；星星这个货币根本不存在，所以装饰和区域这两个"长期目标"整条链没有起点；钻石只进不出。

而**经营层三件套正好是一条完整的正循环**：

```
订单交付 → 好感度（→ 常驻宠物 → 每小时离线产出）
         → 星星   （→ 装饰，纯审美，无数值）
         → 经验   （→ 等级 → 区域解锁 → 真实数值加成 → 更好的订单）
```

一条改动同时接上了"目标""产出""消耗"三端，且**不碰任何现有玩法逻辑**（棋盘 / 合成 / 体力 / 蛛网全部零改动）。

## 03 三套系统的实现

### 3.1 区域（9 个，依次解锁）

| 区域 | Lv | 文档原收益 | **本批实际生效** |
|---|---|---|---|
| 前台大厅 🏠 | 1 | 教程、初始棋盘 | 开局即拥有 |
| 洗护区 🛁 | 3 | 开放洗护类订单 | 体力上限 **+10** |
| 玩耍区 🪀 | 8 | 开放玩具类订单 + 自动型发射器 | 订单金币 **+10%** |
| 餐厅 🍽️ | 14 | 开放零食类订单 + 体力上限提升 | 体力上限 **+20** |
| 训练场 🏋️ | 20 | 开放训练订单 + 稀有订单 | 开放**稀有订单**（5.5×） |
| 午睡区 🛏️ | 26 | 舒适订单 + 离线收益上限提升 | 宠物离线累积 **8h → 12h** |
| 泳池区 🏊 | 32 | 高倍率订单 + 金币产出加成 | 金币再 **+15%**、每单 **+1 ⭐** |
| 诊疗室 🩺 | 38 | 医疗订单 + 道具掉落 | **每天送 1 张升级卡** |
| 摄影棚 📸 | 45 | 拍照生成明信片 | 占位（第二批） |

两条硬规则：
- **顺序解锁**：前一个没建设就不能开后一个 —— `canUnlockRegion()` 里显式挡掉跳级。
- **解锁后立刻重抽订单**：否则新档位（如训练场的稀有订单）要等最长 8 小时才出现，白瞎刚解锁的兴奋。

### 3.2 装饰（11 件，只花星星）

- 3 个系列：通用 5 件 / 猫派 3 件 / 狗派 3 件；每件 Lv1–5，价格 20 → 90 ⭐ 起，逐级 ×1.5~1.7。
- **不给任何数值收益**，这是照抄文档 6.2 的硬约束（原文：装饰的价值是"把玩家的审美投入转化为沉没成本"）。
  代码里**故意没有**"装饰加成"这类字段，并有一条专门的测试锁住这个约束。
- 展示用「乐园繁荣度」= 所有装饰等级之和，**纯展示**。

### 3.3 顾客与常驻宠物（8 只，订单绑定）

- 猫派 4 只 / 狗派 4 只，取自文档第 8 章（布偶猫 / 橘猫 / 暹罗猫 / 英短 / 哈士奇 / 柯基 / 柴犬 / 金毛）。
- 每张订单绑定一位顾客（含 emoji、性格标签、口头禅），交付时**好感度记在发单人头上**。
- 好感满 **240** 转化为**常驻宠物**；转化后不再累积好感（否则数字失去意义）。
- 常驻宠物：**每小时自动产出 24 🪙**，每 5 小时额外 1 💎，**离线最多累积 8 小时**（午睡区 → 12 小时）。
- 顾客出场按时段（文档 5.2）：白天 6–18 点狗 65%，夜间猫 65%。抽顾客时**偏好该链的顾客有 70% 优先出场** —— 让"顾客有性格"落在玩家看得见的订单分布上。

### 3.4 订单档位与倒计时

| 档位 | 需求等级 | 倒计时 | 奖励倍率 | 出现条件 | 权重 |
|---|---|---|---|---|---|
| 普通 | Lv1–2 | 8h | 1.0× | 默认 | 100 |
| 进阶 | Lv3 | 4h | 2.2× | 等级 ≥ 10 | 55 |
| 稀有 | Lv4 | 2h | 5.5× | 等级 ≥ 22 **且训练场已解锁** | 22 |
| 紧急 | Lv4 | 30min | 12× | 等级 ≥ 35 | 8 |

- 奖励四项一次算清（`orderRewards()`）：金币 / 经验 / 星星 / 好感度。基础值沿用文档（15 经验 / 30 金币 / 40 好感），**每提升 5 级整体上浮 20%**（文档 5.1）。
- 星星 = `3 × 档位倍率` + 区域加成 → 普通 3 / 进阶 7 / 稀有 17 / 紧急 36。
- 订单带**倒计时**，到期由每秒的 `tickBusiness()` 自动重抽，不需要玩家操作。

## 04 ★ 与设计文档的三处有意偏离（改动前必读）

### 偏离 1：区域的"解锁收益"整体换过

文档 6.1 的区域表是按 **10 条合成链**写的（洗护链 / 训练链 / 医疗链 / 清洁链 / 货币链…），
本项目现在只有 **4 条链**（`toy` / `care` / `food` / `supply`）。

**处理方式：区域名与等级门槛照抄（那是有意的长线节奏，45 级封顶对应摄影棚），收益重新映射到我们已有的系统上**（体力上限 / 订单金币 / 星星 / 离线时长 / 档位 / 每日道具）。
好处：等链扩到 8–10 条时，只需要往 `REGIONS` 加数据，逻辑一行不用改。

### 偏离 2：订单档位的等级区间被压缩

文档 5.1 的档位表假定链有 **8 级**（需求 Lv1–Lv8）。我们的链实际深度是：

```
toy   3 个普通等级 + 1 顶端（母体）
care  3 个普通等级 + 1 顶端（母体）
food  3 个普通等级 + 1 顶端（纯任务物品）
supply 2 个普通等级，无顶端
```

**处理方式：结构与倍率照搬（4 档 / 1× / 2.2× / 5.5× / 12×），等级区间按实际深度收敛**（`tierLevelRange()`）。
于是"稀有订单要 Lv6–7"在 3 级链上退化成 Lv3，而不是变成永远抽不出的空集。

> **⚠️ 这条偏离带来一个真实的体验问题：**
> 现在 **稀有（Lv3）与紧急（Lv3）落到了同一个需求等级**，两个档位在"要什么东西"上没有区别，只剩倒计时和倍率的差异。
> **档位系统要真正发挥区分度，前提是把合成链从 3 级扩到 6–8 级** —— 这属于"内容扩容"批次，不是本批能解决的。

### 偏离 3：顾客的"偏好链"映射过

文档第 8 章给每个角色写了核心订单偏好（训练链 / 零食链 / 医疗链 / 货币链…），这些链我们都没有。
**处理方式：偏好映射到现有 4 条链**（如"柯基 · 训练链"→ `supply` 礼包链）。角色设定本身一字未改。

## 05 存档兼容

- **不升 `SAVE_VERSION`**：7 个新字段全部按"可加字段 + 默认值"处理，老存档不会因为本次扩展被丢弃。
- 但**订单是例外**：它新增了 5 个字段，结构变化太大，老订单（含 P0 迁移过来的）**直接丢弃重抽** —— 订单是纯临时数据，重抽无损失。
- 逐条清洗：未知顾客的好感、未知区域、越级的装饰等级只清它们自己。
  装饰等级**越级压回上限**而不是删掉（玩家真金白银买的，不能因为数值调整就抹掉）。
- **前台大厅被强制打开**：任何情况下都必须存在，否则整条区域链会断在起点。

## 06 测试

`npx vitest run` → **120 例全绿**（纯逻辑 68 + 整机 52）。本批新增 18 例，重点覆盖：

- 档位：1 级只出普通 / 稀有需要"等级够 + 训练场已解锁"双门槛 / 区间收敛到链深
- 区域：顺序解锁不能跳级 / 体力上限抬高后 `tickRegen` 认新上限 / 加成汇总只算已解锁
- 装饰：星星不够不扣钱 / 满级返回 -1 / **不产生任何数值收益**（硬约束）
- 常驻宠物：每小时产出 / 离线封顶 / **★ 超上限后 `petAt` 必须推到 now**（否则同一段时间被反复结算 —— 这条单测直接抓的是这类"重复发钱"bug）
- 时间驱动：订单到期自动重抽 / 诊疗室每日卡同一天不重复发
- UI：三页签各自渲染正确数量 / 点「建设」真的解锁 / 点装饰按钮真的购买 / HUD 等级格点击打开经营弹窗

构建：`npm run build` 通过（`dist` 139.6 KB JS / 18.7 KB CSS，gzip 53.2 / 4.5 KB）。

## 07 待裁定与已知限制

### 待裁定

1. **装饰要不要补"摆放"？** 现在只做了购买与升级（"装饰墙"形态）。文档 6.2 要求"任意摆放位置 / 更换外观 / 调整朝向 + 多套方案槽位"——那需要一套坐标系统与画布，建议放到第二批，和"猫狗羁绊"（摆在同一区域触发互动）一起做。
2. **诊疗室的每日升级卡，就是"特殊道具获取途径"的答案吗？** 这条正好回答了上一轮遗留的问题 C。如果正式途径是商城购买，那诊疗室应该换成别的收益。
3. **星星的经济量级要不要校准？** 现在普通订单 3 ⭐、装饰 20–90 ⭐ 起（满级约 260 ⭐）。按每天交付 10 单算，约 1 天买一件普通装饰。这个手感需要你实际玩一下再定。
4. **常驻宠物的产出是不是太单一？** 现在只产金币。文档 07-02 还写了"宠物代打（帮忙点击发射器）"，那需要发射器耐久联动，建议第二批。

### 已知限制

- **没有截图验证**：`agent-browser` 未安装（需额外下载 Chromium），所以本轮**视觉布局没有被眼睛看过**。DOM 结构由测试断言覆盖，但间距 / 换行 / 溢出这类问题需要你在浏览器里确认。
- **摄影棚（Lv45）目前是占位**：只有解锁标记与文案，明信片导出未实现。
- **紧急订单的 30 分钟倒计时在 demo 里几乎看不到**：调试行需要加一个"订单立即到期"的按钮来验证（我会顺手补上）。
